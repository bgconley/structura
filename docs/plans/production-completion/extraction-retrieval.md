# Extraction and retrieval completion

Companion to the [master completion plan](../../../STRUCTURA_PRODUCTION_COMPLETION_PLAN.md). Its milestone order and phase gates control this workstream. All packages are planned until their evidence is recorded in the [closure register](closure-register.md).

This workstream adopts the user's decisions to use the existing **Qwen3.8-27B BF16 service on Oxcart** and make **Qwen-native document parsing and extraction the target architecture**, as recorded in [ADR 0008](../../adr/0008-qwen38-27b-ingestion.md) and [ADR 0009](../../adr/0009-qwen-native-document-parsing.md). Model and architecture selection are decided; authenticated integration, implementation, source-fidelity and production-capacity validation remain open. A lightweight deterministic PDF/image layer preserves originals, page inventory, renders and coordinate transforms; Qwen produces the full structured, searchable parse and extraction candidates. Docling is a temporary migration/comparison path, not a mandatory runtime dependency or a veto on Qwen output. This planning update does not change application code or running services. It builds on committed work through `d2820a8`. ADR 0009 supersedes ADR 0006's mandatory-Docling and selection-only restrictions while preserving original-source authority, claims, validation and acceptance policy. Reconcile the June 12 untracked proposals with this accepted target before execution.

Selected existing service: container `qwen38-27b-bf16-mtp-vl-oxcart-server`, served model name `qwen38-27b-bf16-oxcart`, Oxcart port `18012`. Prior read-only inspection confirmed this configuration. An unauthenticated `/v1/models` request returned an HTTP error; no authenticated inference was tested in this planning task. Configuration discovery is not functional acceptance, and the plan does not infer that the authenticated service is unhealthy from that response.

## Current position and non-negotiable outcome

The text-table and KVP lanes, deterministic baseline planner, Qwen vision fallback, candidate admission, typed Claim IR, claim persistence migration `089`, and a document-orchestration implementation already exist. They still assume Docling structure and Qwen3-VL-8B adapters; neither the selected 27B integration nor its native parser is implemented. The orchestration flag is off; normal operation still depends on region jobs and aggregate rendezvous. Reconciliation still reconstructs claims from `normalization_json.regionEnvelope`. Complete these transitions by adapting the existing storage, relational-parse and claim seams to the new parser. Do not preserve obsolete Docling-specific stages merely to retain their current topology.

The June 13 reports demonstrate two-document model-backed pipeline UAT, with review outcomes and no operational failures. They do not establish broad extraction quality, handwriting quality, unseen-document generalization, or model-backed retrieval relevance. The reports have `goldCorpusQuality = not_evaluated`. A successful job that systematically misses present invoice headers is not acceptance of Story 4.3.

Established requirements to preserve:

- Receipt merchant/date/subtotal/tax/total/line items, invoice number/issue date/due date/totals/line items, and EOB payer/provider/patient/claim/service lines with explicit plan-paid and patient-responsibility values where visible (stories 4.2–4.4).
- Trusted fields retain concrete source locators, with usable Viewer navigation; raw model output and normalized extraction remain stored as historical artifacts (app spec §6.4, story 4.5).
- Preserve immutable original bytes, complete source-page inventory, original-page images and usable evidence navigation. Store a versioned, provider-neutral structural artifact containing full searchable content, not only the three typed extraction families. Qwen owns generating that parse; accepted facts remain a separate policy decision.
- Distinguish PDF-native text, model-transcribed text and any temporary Docling output in every derived element and claim. Matching a value against Qwen's own generated parse is not independent source verification. Model-derived values retain their actual origin and required review status; confidence, JSON validity or a fabricated locator cannot authorize promotion.
- Use the same Qwen3.8-27B BF16 engine for parsing/transcription, classification, semantic organization and typed/visual extraction. Blackbird's text and visual embedding services cover both ingestion indexing and query-time search, preserving their separate 1536/2048-dimensional model/index contracts. Qwen8B, Granite and Docling are optional historical/comparison paths, not mandatory default ingestion services or agreement gates.
- No hidden semantic rescue pass, silent fixture fallback, unreviewed model auto-promotion, fabricated required fields, cross-household evidence, duplicate current results after retries, or loss of human corrections.
- Quality outcomes remain `extracted_cleanly`, `needs_human_review`, `insufficient_signal`, or `no_extraction_target`; `pipeline_failed` remains an operational defect. Safe abstention passes safety assessment but can still fail utility/recall assessment on a readable document.

## Dependency sequence

Define the neutral parse/provenance contract and implement shared ownership/fencing before publishing new parse generations. In parallel, build private source annotations, integrate the authenticated Oxcart 27B service, and measure Blackbird ingestion/query embeddings. Implement the deterministic source layer and bounded Qwen-native parser, then complete evidence admission, authoritative claims and document orchestration. Cut over parse/search projections with preserved history and a tested rollback, and retire the temporary Docling path after acceptance. Run full parsing, extraction and retrieval gates across both hosts before Phase 9. No A/B win over Qwen8B, Docling agreement, or separate approval to investigate this already-selected architecture is a prerequisite; activation depends on the documented source-fidelity, recovery and capacity gates.

The shared job-lease work belongs in the project's job-infrastructure package and is a dependency here, not a second independently designed queue system.

### X-02 — Fence extraction runs and all worker writes

Problem: current annotation supersession only marks rows already present. Old jobs can still load a superseded annotation and write current output after a rerun. Generic job completion/heartbeat also lack attempt ownership. Increasing the lease timeout alone does not fix either defect.

Implementation:

- Add a durable document-run identity and monotonic generation, initially bound to the original asset/hash and requested parser/model profiles, then to the produced parse asset/hash before derived claims publish. Increment it transactionally when an authorized rerun starts. Record schema details in the run-ownership ADR before coding; allocate migration numbers from the current repository sequence rather than reusing `089`.
- Add a unique lease/attempt token returned by job claiming. Heartbeat, completion, failure, cancellation acknowledgement, artifact publication, downstream enqueue, and extraction writes must check job id plus live attempt token. A stale worker may not renew a newer worker's lease or mark another attempt complete.
- Use one stable lock order for document/run/job rows across enqueue, cancellation, publication, and retry. Validate both active run generation and lease ownership in the same transaction that publishes parse structures, claims/candidates/current extraction and review records. Checking only before a model HTTP call is insufficient.
- Heartbeat independently while rendering/parsing/model requests execute, using a bounded worker lifecycle component shared across workers. Stop publishing when ownership is lost; cancellation should stop further model requests when practical and always prevent publication. Reclaiming a lease must not require another successful job in the same queue to make health visible.
- Supersession retires pending work for the old generation, current region outputs, aggregate outputs, current asset projections, and open generation-specific review tasks as one coherent transition. Preserve immutable history and accepted human facts. Keep the previous published snapshot explicitly labeled while the new run is processing; never mix generations in one current view.
- Bind downstream indexing/relationship refresh to the published generation and make enqueues idempotent. An obsolete run must not refresh search with stale projections.
- Stage external files before the final transaction; clean abandoned/unreferenced objects with the existing storage cleanup seam. Do not hold a database transaction open over inference.

Required deterministic/Postgres integration scenarios:

1. Old worker is paused after inference; rerun B publishes; worker A resumes and cannot change current claims, aggregates, candidates, assets, review tasks, search projection, or job B.
2. Lease A expires, worker B claims the same job, then A heartbeats/completes/fails. All A operations are rejected without harming B.
3. Cancel during model inference, terminate a worker mid-document, retry after partial claim persistence, duplicate-deliver a task, and rerun while queued work exists.
4. Qwen reparse or migration from Docling changes structural IDs while extraction is active; old parse-bound evidence cannot become current. Historical locators remain resolvable against their original generation.
5. Human-confirmed and human-corrected values survive retries and new extraction proposals; new conflicting candidates are reviewable with history.

Exit: zero stale-owner writes; exactly one published extraction generation; no duplicate current aggregate/candidate/asset projection for one logical result; all injected operational failures recover or terminate with an explicit reason. Run the chaos matrix with resident workers and the selected Oxcart 27B/Blackbird retrieval topology before E5 defaults on; inject model-boundary faults without stopping the shared Oxcart service.
